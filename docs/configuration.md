# Configuration

agentcheckup works without configuration. To change targets or rule severities, add
`agentcheckup.config.json` to the directory you scan.

```json
{
  "$schema": "https://raw.githubusercontent.com/mustafakbaser/agentcheckup/main/schemas/config.schema.json",
  "targets": ["claude-code", "codex", "cursor"],
  "rules": {
    "instr/claude-md-too-long": ["warn", { "maxLines": 300 }],
    "skill/non-portable-field": "off"
  },
  "ignore": ["test/fixtures/**"],
  "overrides": [
    {
      "files": ["examples/**"],
      "rules": { "skill/description-quality": "off" }
    }
  ]
}
```

The configuration is JSON on purpose. agentcheckup never executes code from the repository it
scans, so JavaScript or TypeScript configuration files are not supported.

## Fields

| Field       | Type         | Meaning                                                                                                                                                                                         |
| ----------- | ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `targets`   | platform ids | Agents to check against. Rules about other agents are skipped. Default: all of `claude-code`, `codex`, `cursor`, `copilot`, `gemini`, `windsurf`, `cline`. The `--targets` flag overrides this. |
| `rules`     | object       | Per rule: `"off"`, `"info"`, `"warn"`, `"error"`, or `[severity, options]`.                                                                                                                     |
| `ignore`    | globs        | Files to skip, relative to the scanned directory. Files ignored by `.gitignore` are skipped already.                                                                                            |
| `overrides` | array        | Change rule severities for files matching `files`. Later overrides win. Options can only be set in the top-level `rules`.                                                                       |

Globs use [picomatch](https://github.com/micromatch/picomatch) syntax and match dotfiles.

Unknown rule ids in the configuration produce a warning on stderr. Unknown fields are an error,
so a typo cannot silently disable a check.

## Inline suppressions

Suppress one finding on the next line, with a reason:

```markdown
<!-- agentcheckup-disable-next-line instr/import-unresolved -- generated by our docs build -->

@docs/generated/api.md
```

Suppress rules for a whole file:

```markdown
<!-- agentcheckup-disable-file skill/body-too-long -- reference skill, loaded on demand -->
```

Inside YAML frontmatter, use a YAML comment:

```yaml
---
name: deploy
# agentcheckup-disable-next-line skill/non-portable-field -- Claude Code only
when_to_use: Before every production deploy
---
```

Rules:

- The reason after `--` is required. A directive without one is reported and has no effect.
- A directive that no longer suppresses anything is reported, so stale suppressions do not
  accumulate.
- JSON files cannot hold comments. Use `overrides` for them.
- `--untrusted` ignores all inline directives and the repository's configuration file. It also
  reads agent configuration that the repository's `.gitignore` matches, because agents load
  committed files whether or not they are ignored.

## Baselines and the gate

`--baseline <report.json>` compares a scan with the JSON report of an earlier one, usually the
base branch of a pull request:

```sh
agentcheckup --context --format json --output base.json --fail-on none   # on the base
agentcheckup --baseline base.json --gate security                         # on the change
```

- Findings match by fingerprint and are marked `new` or `unchanged`. `--fail-on` counts new
  findings only; the score still covers every finding.
- `--gate` names the security-relevant changes that fail the run: `mcp`, `mcp-unpinned`,
  `permissions`, `hooks`, `env`, `unicode`, `security` for all of them, or `none`. Removals
  never trip it. `--gate` without `--baseline` is a usage error.
- `--context` on the base scan adds the load plans, so the comparison also shows the change in
  session-start context per agent.
- The baseline is read as untrusted input: at most 64 MiB, a regular file (not a symlink), and
  only a report with a supported `schemaVersion`. Anything else exits with code 2. A baseline
  written with another ruleset is accepted with a warning: findings from rules it did not run
  count as new.

## Paths in GitHub Actions

Report paths are relative to the current directory. When `GITHUB_WORKSPACE` is set and the
scanned directory is inside it, the `github` and `sarif` formats use paths relative to the
workspace instead, because GitHub resolves annotation and SARIF paths against the repository
root. Running the CLI from `$RUNNER_TEMP` on `"$GITHUB_WORKSPACE"` therefore annotates
`.mcp.json`, not `../../work/repo/repo/.mcp.json`.

## Exit codes

| Code | Meaning                                                                                                                                               |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0    | No findings at or above `--fail-on` (default `error`), the score meets `--min-score`, and no gate tripped. `context` exits 0 unless `--gate` trips.   |
| 1    | Findings at or above `--fail-on` (only new ones with `--baseline`), a score below `--min-score`, or security-relevant changes caught by `--gate`      |
| 2    | Invalid arguments, configuration, `--cwd` or `--agent`; `--gate` without `--baseline`; a baseline that cannot be read or used; an unusable `--output` |
| 3    | Internal error: a rule, a loader or the scanner crashed                                                                                               |
